# 通用宿主适配卡

既不是 Claude Code 也不是 Codex 的宿主（如 ZCode）用这张卡。前提只有一条：能启动一个**不带当前会话历史**的子代理或子会话，并给它一段提示词。做不到就停下说明宿主不受支持，不要在主会话里亲自执行工单。

```text
HOST=generic
EXTERNAL_ENGINE=codex        # 默认值。宿主模型与 Codex 同家族时，在 .reproduce.json 里设 external_review.engine 为 claude
```

所有 flow 命令带 `--host generic`。外审引擎必须与宿主模型不同家族，这一点内核无从判断，由你按上面一行配置。

## 把工单变成派发

- 给子代理的提示词就是工单的 `prompt_inline`（「读取任务文件并严格按它执行」），原样填写。宿主支持给任务命名时，名字填 `step_id`。
- 宿主没有命名角色：任务文件开头写着角色合同的路径，子代理会先读它。
- 宿主支持并行就把同一批 `dispatch` 工单并行派出，否则逐张派；都返回后再 `flow done`。
- 子代理不嵌套派发、不改 `state.json`。

## 后台外审

`exec` 工单：执行工单里的 `command`（带 `--detach`），再执行 `flow wait <id>`，没等到就再执行一次。宿主不允许后台进程时去掉 `--detach` 前台执行，命令超时放到 30 分钟以上。外审失败后内核自动降级为同宿主盲审（`same_host_fallback`，评级封顶 B），再不行记为跳过。

## 向人提问与凭据

把审阅包要点、各选项的后果和 `[<检查点 id> · <短码>]` 发给人，等人答复；人久未回答时保持停下。人在自己的终端执行 `flow decide` 并输入短码是终端级凭据，你代为执行是自述级。

## 计量与禁读

宿主的会话记录格式内核不认识时，用量只有输入侧账本（任务文件字节数、内核调用次数、墙钟），禁读清单只靠任务文件里的纪律约束。
