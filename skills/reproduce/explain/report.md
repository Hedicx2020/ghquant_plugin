# report（报告汇总）

顺序：内核统计覆盖率 → 写报告前的机器预检（矩阵没有未到终态的行、假设登记簿没有未回填的回看）→ 不过就派 `report.docfix`（验证者）补齐 → 内核生成素材摘要 → `report.main`（报告者只汇总不新增结论）→ 内核把达标计数、指标对比总表和假设登记簿全文嵌进报告、渲染结果页 → 再做一次一致性预检（报告里手写的计数或数值与机器结果对不上就退回报告者，验证文书的问题退回验证者；结论写在 `audit/precheck_report.md`）→ 过门禁 → 进入最终评审。

## G-FN-1、G-FN-2

报告不存在，或缺必需的二级章节（结论、指标对比、假设登记簿、迭代历史、审计回应、残余偏差、未复现清单、复跑指引）。重派 `report.main`。

## G-FN-3、G-FN-4

矩阵里还有 pending / in_progress 的行，或假设登记簿里还有没回填的占位符。内核重做预检并派 `report.docfix` 补齐，不必重写报告。

## G-FN-5

被拒绝的外审意见没有出现在报告的遗留清单里。重派 `report.main`：rejected 的意见编号必须原样出现。

## G-FN-6、G-FN-7

覆盖率统计没写入，或结果页 `final_report.html` 没生成、里面没有指标对比总表。都是内核自己的产物：内核重新统计、重新嵌入并渲染，不用派人。连续不过会熔断，把这次的门禁原文交给人。

## pre_report

单步模式下写报告前停一次，审阅包里是结论、覆盖率、三道外审的引擎与降级情况、被拒绝的意见。
