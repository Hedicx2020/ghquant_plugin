# code_audit（代码审计）

先由内核做静态预筛与备料（R 类数值字面量在 `src/` 的命中、B 类参数与 `config.py` 的一致性、取数是否都经 `data_path()`、`common/` 签名），只作外审输入，不生成意见。

同批发出：代码外审、实现内审（medium，或带 ml 标签的 easy；hard 已在各 milestone 做过）、以及与审计并行的预跑验证（medium / hard 且不带 ml 标签）。之后是「裁决 → 修复 → 复审」循环，见 `flow explain review_cycle`。

修复改了 `src/` 之后，预跑的验证结果作废，验证阶段会整批重出。

## G-CA-1

外审产物或回应表不存在。外审失败走降级链后这一项随之满足；仍不过内核重新汇总。

## G-CA-2

按难度该有的实现内审记录缺了。重派内审。

## G-CA-3

内审记录里有「判定: not_found」——空壳实现。派 `code_audit.gatefix`（coder）补实现，再重派内审确认。

## G-CA-4、G-CA-6

回应表行数与外审意见数对不上，或有 major 没回应。内核重新汇总并重发裁决工单。

## G-CA-5

还有 critical 没闭环（未来函数、硬编码结果、方向相反这一类）。接受并修复后经复审确认；这类意见不得拒绝或搁置。
