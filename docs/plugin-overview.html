quant-report-reproduce
量化研报复现流水线

给它一份量化研报 PDF，它产出与原文逐项对齐的策略代码、回测结果，和一份带可信度评级的复现报告——中间的提取、规划、实现、验证、审计、迭代，由带门禁的多 agent 流水线完成；每一步派谁、读什么、过不过关由一个确定性的内核决定，需要人拍板的地方它会停下来等你。

复现流水线全景

一份研报从 PDF 到最终报告要过 12 个阶段。每个阶段结束时由机器门禁（check_gates）逐项核验产物，PASS 才放行，FAIL 按预设分支修复重来——口头声称完成无效，判定只认文件和数字。v3 起门禁由内核在阶段收口处自己执行并记入事件流，不再依赖编排会话「记得去跑」。

支持五类研报——选股因子（factor）、择时（timing）、资产配置（allocation）、固定收益（fixed_income）、机器学习（ml）——并按 easy / medium / hard 三档难度自动分诊，差异化投入：难度越高，审计越密、迭代额度越多、无依赖模块并行实现。

安装与首次配置

环境要求

  • uv（硬前置）：所有工具经 uv run 调用；依赖缺失时在工作目录执行 uv sync。
  • 订阅档位：8 个子 agent 中 7 个使用 opus，建议 Max 档位。可开经济模式让机械性角色降档，或自行编辑安装副本 agents/*.md 的 model 字段下调（复现质量自负）。
  • 外审引擎（软前置）：外审由另一家族的命令行工具执行——在 Claude Code 里跑用 codex CLI，在 Codex 里跑用 claude CLI。未安装或额度用完都不断链——自动降级为同宿主替身盲审（同一审查任务、独立上下文、意见照样逐条回应闭环），替身也不可行才标记跳过；发生失败性降级时最终报告如实标注，可信度评级封顶 B。装好 / 额度恢复后无需重新配置，下次运行自动启用。
  • python3（软前置，仅 Claude Code）：两个钩子脚本靠它启动——读文件前的禁读护栏、检查点待决时记下你的原话作为放行凭据。python3 不在 PATH 上时钩子不生效，流程照常，放行记录降为「自述」级并在看板标出。

三步开始

  1. 安装插件（两步）：/plugin marketplace add https://github.com/Hedicx2020/ghquant_plugin 注册源，然后 /plugin install quant-report-reproduce@hedi-quant 安装（重启会话生效）
  2. 进入你自己的工作目录（任意空目录），运行 /reproduce setup——分两批问卷收六项配置，随后自动落地：.reproduce.json 配置、templates/（达标标准与各类模板）、common/（内置回测库）、.codex/agents/（Codex 侧角色）、pyproject.toml、目录树，并检测 uv / Python 依赖 / codex / claude / python3，最后体检一遍你的数据目录。
  3. 看一眼体检结果（见下「数据体检」），把 PDF 放进 reports/，运行 /reproduce reports/xxx.pdf。

setup 幂等可重跑：已有配置默认保留，你改过的模板文件永不被覆盖（插件侧更新只列清单提示，不动你的文件）。

偏差是「相对偏差」：判定式为 |复现值 − 研报值| ÷ |研报值|。研报年化 10%、容忍 5% ⇒ 允许区间 9.5% ~ 10.5%（不是 5%~15%）。研报值越小同样容忍越苛刻，所以近零指标（如因子 IC）在内置标准里配有绝对偏差兜底（abs_eps），自定义容忍不改变这些特殊判定的语义。

优先级固定：命令行显式参数 > .reproduce.json > 内置默认。配置文件可直接编辑，或重跑 /reproduce setup 选「重新配置」。

数据体检与缺口处置

v3 之前，数据够不够用靠规划 agent 对着一份手写的数据目录来判断，机器不查——目录写错一行，缺口要到写代码时才暴露。现在改成机器先查清，缺了由你选怎么办：

  1. 数据目录体检（setup 与每次建案时自动跑，只读元数据，秒级）：记下数据根目录里每个文件的字段、行数、日期起止，带证券代码的表再算每年的标的数与交易日数，生成一张「数据实况表」交给规划 agent。手写的 templates/data_catalog.md 降为说明性文字，与实况对不上的地方会列为提示。
  2. 数据需求体检（规划阶段内，不花 token）：复现计划里的每条数据需求逐条核对——文件在不在、字段齐不齐、区间盖不盖得住、某些年份标的数有没有塌陷、主键有没有重复、财务数据有没有披露日列。结论四选一：通过 / 部分满足 / 缺失 / 未机检（数据库、接口等查不了的来源）。
  3. 缺口处置（只能由你决定）：系统停在检查点，逐条列出缺什么、影响哪些要素与指标、是不是核心，然后等你选：
处置含义之后
补数据你去把数据补上暂停；补完后重新体检，通过即继续
等价替代用本地的等价数据代替（严格模式下须切到实验模式）登记为假设，继续
缩小范围只在有数据的区间或标的上复现登记为假设，继续
先用 mock 试跑用模拟数据先把代码和流水线跑通整轮只算试跑：不出达标结论、不写报告，停在「试跑完成」等真实数据
砍掉相关要素把依赖这份数据的要素标为不可行，其余照做继续
终止放弃这份研报案例结束
mock 数字不会混进结论：试跑的结果写在单独的目录（output/<id>/results_mock/）；每次运行读了哪些文件、各自是真实还是模拟，都记在数据清单里；门禁会拦下「真实结果里出现过模拟数据」的情况。真实数据到位后，代码没变的部分（编码、代码审计）继续有效，只重跑验证。

财务数据仍须按披露日（info_publ_date）对齐，代码审计会逐点核查未来函数。复现代码一律经 common/data_loader.py 的 data_path() / read_table() 取数，试跑与正式运行靠它们切换数据目录，不需要为 mock 另写分支。

运作方式

三方分工：内核（一段确定性的 Python 程序）决定下一步派谁、读什么、交什么、门禁过不过；主会话只负责照单派发、把内核的话转述给你、把你的决定交回内核；所有内容产物（提取规格、复现计划、代码、验证结论、最终报告）一律出自子 agent，所有达标判定一律出自门禁工具按标准重算。这个分离是防偷懒设计的根基——生产者、验证者、判定者三方互不为师。

内核与工单：流程写在代码里

v2 的流程写在给模型看的文字里（技能说明与各阶段执行卡），靠编排会话自己记得「下一步该做什么、门禁跑了没有、这里该不该停」。跑了十份研报后发现三类问题反复出现：编排会话自己成了最大的 token 消耗者；返工派发没有记录；该停下等人的地方被它自行越过。v3 把流程控制搬进了代码：

flow next <id>        # 内核给出工单：派哪个角色、让它读哪个任务文件、该交回哪些文件
   ↓ 主会话照单派发子 agent（同一并行组的工单一起派）
flow done <id> <步骤>  # 内核点收：查产物 → 合并回执 → 跑门禁 → 记事件 → 记用量 → 刷新看板 → 给出下一批工单
   ↓ 循环，直到内核返回 halt（停在某个检查点，等你决定）
  • 任务文件：内核为每一步拼好一份任务文件，只装这一步需要的内容——从规格书、假设登记簿、覆盖矩阵里逐字切出相关片段，其余只给一行索引。子 agent 缺什么可以按编号向内核取原文。原始文书始终是权威来源，切片只是只读的派生物。提取、规格审计与外审仍然读全量，不切。
  • 回执：子 agent 不再直接改覆盖矩阵和假设登记簿，而是把要回填的内容写进回执，由内核核对「这一行归不归你这一步、状态变化合不合法」后合并。并行的多个 agent 因此不会互相覆盖。
  • 确定性的事由内核自己做：填外审提示词、汇总多轮外审意见、统计覆盖率、生成对比总表、拼假设登记簿进报告、渲染结果页，都不再经过模型。
  • 可以退回：步骤表判断不了的情况，任何阶段都能退回「执行卡驱动」（v2 的方式）由编排会话按卡处理，做完再交还内核；停下等人的守卫在状态层，退回执行卡也绕不过去。

内核只依赖 Python 标准库与 pyyaml，与宿主无关：Claude Code、Codex 和其他「读任务文件」式的宿主各有一张薄适配卡，说明怎样把一张工单变成一次子 agent 派发。

六条硬规则

  1. 推进只经内核：主会话不直接改状态文件与事件流，不手拼派发提示词。
  2. 门禁即代码：门禁由内核在阶段收口处执行并记入事件流；未通过项原样呈现，FAIL 不进入下一阶段，口头声称通过无效。
  3. 检查点只由人放行：内核返回「停」就停，把审阅包交给你；你答复后才执行放行命令，并记下你的原话。没人答复就停着，不替你选。
  4. 编排与生产分离：主会话严禁亲自撰写规格、计划、代码、验证结论、最终报告。
  5. 表外派发要登记：步骤表之外确需派人，走专门的临时派发命令，写明原因，有次数上限，照样入账。
  6. 达标判定唯一出口：pass / partial 只能由门禁工具按 standards.json（叠加你的偏差容忍）重算得出。

v2 的另外几条（产物逐一点收、状态先行、审计意见逐条回应）没有取消，而是从「要求编排会话遵守」变成了内核的固定动作：点收、写状态、把外审意见登记进回应总表都由代码完成。每条外审意见怎么处置（采纳 / 说理拒绝 / 搁置）仍由主会话判断，但 critical 不许拒绝或搁置——它若坚持认为不成立，内核会开检查点交给你裁决。

八个子 agent：各司其职、互相制衡

quant-extractoropus
研报忠实提取者

只回答「研报说了什么」：产出规格书、覆盖矩阵、歧义清单三件套，每条要素带页码引用。只陈述不设计，防止提取阶段掺入主观发挥。

quant-planneropus
复现设计者

只读规格书不读 PDF（信息隔离），做类型/难度分诊、数据可得性映射、里程碑拆分、歧义裁决，产出复现计划与假设登记簿。

quant-coderopus
策略实现者

按计划切片实现策略代码并回填矩阵实现位置。只许冒烟运行，不得自行宣布验证结论——写代码的人不给自己打分。

quant-verifieropus
运行验证者

亲自跑 main.py、逐项对数产出对比表与图表、随跑随记证据链；触发时做扰动测试（改数据截止日重跑，指标必须变化——抓硬编码造假）。不采信 coder 声明。

quant-auditoropus
对照审计者（三模式）

spec / code / result 三种模式：查提取有没有漏、实现是否忠实原文、结论有没有编。只拿文件不拿被审者自述，关键数值独立重算。

quant-oos-analystopus
样本外表现分析者

复现达标后，把策略原样延伸到研报回测区间之后的数据上运行，评估效应延续/衰减/失效。红线：严禁改动策略逻辑与参数——任何为改善样本外表现的调整都是数据窥探。

quant-reportersonnet
报告汇总者

把全部管线产物汇总为最终报告（含可信度评级与全量假设登记簿）。只汇总不新增结论、不重算指标——数字一律引用验证产物。

硬约束：8 个子 agent 不得再派 agent、不碰状态文件与事件流；哪些步骤可以并行由内核在工单里标出（无依赖里程碑的编码、验证与下一段编码重叠、代码审计与运行验证、结果审计与样本外分析），主会话照单一起派。Claude Code 上另有一道读文件前的钩子：按在途步骤核对该角色的禁读清单（比如规划者不得读研报原文、任何人不得直接读扰动结果与运行缓存），命中即拒绝；Codex 没有对应的拦截点，改为事后从会话记录里核对并在看板标出。

角色合同的正本是 agents/*.md。Codex 侧的角色文件由脚本从正本生成；工作目录里的副本落后于正本时，内核会自动改用通用子代理并把合同全文内嵌进派发，不会拿旧合同干活。

三层审计体系：防偷懒、防遗漏、防虚报

层执行者防什么手段
外审三审查点另一家族的引擎，只读调用（Claude Code 里跑用 Codex，Codex 里跑用 Claude Code）提取漏抄 / 实现走样 / 结论造假规格审计（盲提取对照：外审不看规格书独立抄一遍研报数值再逐格对比）、代码审计（公式对照 + 未来函数）、结果审计（数字与产物一致性）。每条意见编号进回应总表，critical 必须修复并复审通过。
内审quant-auditor同上，独立视角三模式对照审计；hard 难度逐里程碑插入实现忠实性审计；ml 类无视难度必审（训练泄漏数值验证抓不到）。
反虚报核查quant-auditor（result 模式）+ 机器检查项「声称做了实际没做」K 系列（K1–K8）：结果过于完美嫌疑、声称通过实际未改等；E 系列（E1–E6）证据链：运行日志、产物新鲜度、通过数亲自重数、图表逐张数值级核验。

v3 重做了外审的执行方式（三个审查点共用）。此前外审只拿到一串文件路径，要靠几百次命令一段段读文件，推理强度跟着全局配置走，还会自己再分出子代理，于是又慢又贵、动辄超时作废。现在：

  • 输入包：内核把要审的文件带行号拼好，随提示词一次送入；放不下的按优先级只列路径，审查方仍可自己去读。
  • 参数显式指定：首轮默认 high 推理强度、复审 medium；调用时关闭多代理。
  • 差量复审：第二轮起只给上一轮的意见与回应、以及改动处的差异，核对每条意见是否闭环、改动有没有引入新问题；改动面过大时自动整体重审。
  • 盲提取拆成两次调用：第一次只给研报原文与表格，第二次才给规格书和第一次的产出——「盲」不再只靠审查方自觉，事后还能从会话记录里核对。
  • 后台执行与重试：时限 30 分钟（可配）；超时降一档推理强度原样重试一次，仍不行才走降级链，不缩减输入。
  • 结果一致性预检：派结果外审之前，机器先核四件事——核心要素在对比表里都有条目、对比表的数值与原始指标文件一致、空值不被计为通过、文书里的计数和数值与机器结果一致（含修复后残留的旧数）。此前结果外审提出的严重意见几乎都属于这一类，机器能查的就不留给外审。

迭代引擎

首轮验证如有指标超差，进入迭代：每轮由 diagnoser 归因 → coder 定向修改 → verifier 全量重跑对数，三件套（诊断 / 修改记录 / 复验对比）落档留痕。迭代受两道约束：

  • 轮数上限：难度默认 3/5/6 轮，或你在 setup 配置的全局值；
  • 防兜圈规则：同一指标连续三轮无实质改善触发红线，diagnoser 必须改判 stop_partial（接受局部达标，残余项逐条归因）或 blocked（上报阻塞），不许无限重试。

从第二轮起，内核会给诊断者附一份机器生成的摘要：各指标逐轮的偏差变化、同一指标连续两轮改善不足一成的预警、历史上已排除的假设原文——防止绕回已经试过的路。

检查点：停在哪、谁放行

流水线只在两种状态下等人：paused_blocked（遇到必须人工裁决的问题）和 awaiting_review（等你评审）。v3 把「具体停在哪、为什么停、有哪些选项」做成了检查点：每个检查点带一份机器生成的审阅包（几 KB，要点带页码或文件出处）和一组固定选项。处于等待态时内核只返回「停」，门禁转绿也不会自动放行——任何自动驱动（包括 /goal 无人值守）都冲不过去。

类别检查点什么时候出现
只能由你决定数据缺口处置、等数据、模拟数据规格确认、试跑完成、可行性阻断、阻断级歧义、迭代受阻、严重意见有争议、同一份 PDF 已有案例、最终评审任何模式下都会停。唯一的例外是你在建案时用 --on-missing mock 预先授权过：数据缺口与模拟数据规格两项按「先试跑」自动处理，并记为「策略」级放行
流程自己走不下去熔断（同一门禁检查项连续 3 次不过）、重派次数用完、复审 3 轮仍有严重意见未闭环、子 agent 报告受阻、步骤表派不出下一步、状态文件被改动过、长时间没有进展、超出预算任何模式下都会停
评审类（可选）规格定稿、计划定稿、每个里程碑完成、验证完成、迭代每轮interactive 模式；或用 --until <阶段> 指定一次性停点、--step 每步都停
只留痕不停外审降级、按假 FAIL 重跑了一次验证、限额内的重派记入事件流和看板

评审类检查点上你有五种决定：通过；修改后继续（口述要改什么，内核交给负责的角色去改，改完重过门禁再回到同一个检查点，最多 3 轮）；我已经直接改了文件（内核重新核对后回到同一个检查点）；回退到更早的阶段或里程碑重做；终止。

放行记录带凭据等级。每次放行都记下你的选择和原话，并标明凭什么算数：钩子级——Claude Code 的钩子在你提交输入时记到了带检查点短码的原话；终端级——你在自己的终端里执行放行命令并输入了短码；自述级——只有编排会话的转述。自述级会在看板和最终报告附录里标出来。这防的是编排会话「顺手替你点了通过」，不防蓄意伪造。

看板与用量

  • 看板：每次点收后内核重新生成一个静态页面 workspace/<id>/board.html（不起服务，浏览器直接打开，运行中自动刷新）——当前在做哪一步、等谁、停了多久，阶段 × 里程碑的进度，待决检查点，门禁明细，用量，假设与外审台账，返工派发清单。全部案例的总览在 workspace/board.html。
  • 事件流：每个案例一份只追加的事件记录（events.jsonl），带哈希链；状态文件或事件流被内核之外的东西改过会被发现，并开检查点让你确认。
  • 用量：每张工单的任务文件大小与耗时必有记录；读得到宿主会话记录时，再把未缓存输入、缓存读写、输出分开记到每一步；外审进程的用量同样入账。flow cost <id> 按阶段、角色、步骤汇总。
  • 失效标注与重开：内核记下每一步读过哪些片段。你改了规格、计划或某条假设后，flow stale <id> 列出哪些已完成的步骤因此过期；reopen 从最早过期的地方重做，旧产物归档不删。

达标判定与可信度评级

每个量化指标按「研报值 vs 复现值」的相对偏差判定，容差来自 templates/standards.json（分类型精细配置，落地在你目录里可手工细调）叠加你的全局偏差容忍。特殊语义独立判定：近零指标走绝对偏差（abs_eps）、方向类指标查同号、成交笔数类查数量级、定性结论（如分组单调性）按预期字符串核对。

最终报告给出 A / B / C 可信度评级：

评级判据
A覆盖率 ≥ 90%（核心要素 100%）＋ 三外审通过 ＋ 零 critical 遗留
B核心要素覆盖 100%，但支线有缺，或外审有失败性降级（外审引擎不可用改由同宿主替身盲审，或替身也不可行被跳过）；外审档位 standard 未触发的配置性跳过不算降级、不封顶
C存在核心要素未复现或 major 意见遗留未回应——报告结论区显著提示成因
评级 C 不一定意味着复现质量差：数据客观缺失（如某指数系列本地零覆盖，经穷尽核实）导致核心支线不可行时，字面判据同样触发 C——报告会写明成因与主线结论是否受影响，残余偏差 100% 归因后才能出报告。

两种复现模式：严格 vs 实验

默认为严格模式（数值对齐原文）。复现海外报告/论文而本地没有原文市场数据时，用实验模式做市场迁移：/reproduce reports/us_paper.pdf --experimental。

维度严格模式 strict（默认）实验模式 experimental（市场迁移）
目标复现值与原文数值在容差内对齐验证「该方法在迁移市场是否成立」——效应存在与否都是有效结论
数据按原文数据源（本地缺失→降级或阻塞）等价替代并逐条留痕：美国 CPI → 中国 CPI、SPX → 沪深300……全部登记假设登记簿（market-transplant 条目）
达标判定逐指标容差重算（相对偏差/绝对偏差/同号/量级），超差触发迭代修正数值对齐判定整体豁免——只核每个原文指标有迁移市场产出；原文值仅作对照参考；迭代阶段天然跳过
不变的部分提取忠实性、代码审计（公式对照/未来函数）、反虚报核查（数字与产物一致、结论不夸大）、样本外分析、人工评审闸门——两种模式完全一致
明确提示—强制：结果页顶部醒目声明框 + 徽章，最终报告必含「市场迁移声明」章节（门禁核验，缺失过不了报告关）
切换权只在你手里：未加 flag 而规划发现原文市场整体不可得 → 系统挂起呈报「建议实验模式」等你裁决，agent 无权自行切换

五个典型场景

场景一：新起复现 + 无人值守。起跑后系统会打印一条可复制的 /goal 命令，粘贴即启用跨会话自主推进——推进到四个终态之一（等待评审 / 完成 / 局部完成 / 阻塞挂起）自动停下汇报。目标措辞被刻意设计成「到达终态即停」而非「复现成功」，防止驱动层为达标冲撞人工闸门。

/reproduce reports/treasury_timing.pdf
# → init 完成后照提示粘贴 /goal 命令，然后可以去干别的

场景二：评审后改假设。报告完成后系统挂起等你评审。假设登记簿里每条自动假设（尤其高亮的 major-auto 级）都附了一条现成的 revise 命令——不认同就复制改口径：

/reproduce revise treasury_timing --assumption AS4 --new-text "涨跌幅采用结算价口径而非收盘价"
# → 先报告影响面与重跑范围，你确认 → planner 改假设 → 只重跑受影响链路 → 报告更新 → 回到评审

场景三：断点续跑。会话中断、机器重启都不丢进度——状态文件是唯一真相源：

/reproduce status            # 案例一览表：编号 | id | 状态 | 阶段
/reproduce continue r3       # 编号缩写即可，不必敲全名

场景四：中途打断校验。不想等它一口气跑完再看——让它在你关心的地方停下：

/reproduce reports/xxx.pdf --mode interactive   # 规格定稿、计划定稿、每个里程碑、验证完成各停一次
/reproduce reports/xxx.pdf --until plan         # 只在规划结束时停一次，其余自动
# 停下后看审阅包（workspace/<id>/reviews/）或看板，然后告诉它：通过 / 要改什么 / 我已经改了文件 / 回退到哪里

你直接改了规格、计划或假设登记簿也没关系：内核会比对出改了哪些片段、哪些已完成的步骤因此过期，重过所属阶段的门禁后再继续。

场景五：数据还没到齐，先把流程跑通。规划阶段体检出缺口后停下问你；选「先用 mock 试跑」：

# → planner 起草模拟数据规格，你确认 → 生成模拟数据 → 编码、代码审计照常 → 验证只查「跑得通、产物齐、指标算得出」
# → 停在「试跑完成」。真实数据补齐后：
flow data recheck <id>       # 重新体检；通过后只重跑验证（数据结构与模拟规格不一致的，相关编码一并重做）

常见问题

我怎么知道每个案例的 id？

三个途径：① 起跑时终端会明示「本案例编号 rNNN（report_id=rNNN_短名）」——新案例的 id 由系统自动编号，形如 r001_style_factor（三位顺序号 + 看名知义的语义短名，短名取 PDF 文件名或研报标题）；② 任何时候跑无参 /reproduce status，得到按编号排序的案例一览表（编号、id、类型、状态、当前阶段）；③ 目录名即 id：workspace/ 下每个子目录对应一个案例。日常引用不必敲全名——continue/status/revise/accept 都接受编号缩写（r3、r003、3 等价）或唯一前缀，输入有歧义时系统会列出候选让你挑。想用自己的命名跑 --id 自定义名 即可（不强加编号）。

没装外审用的命令行工具，或跑到一半额度用完了，会怎样？

都不会断。外审走两级降级链：一级降级——派一个全新的、不带任何历史上下文的子 agent 作「外审替身」，执行与外审引擎完全相同的审查任务（同一份审查指令、只读原始材料、禁止接触流水线过程叙事），意见照样逐条编号进回应总表、critical 照样必须修复闭环；二级降级——替身也交不出来（罕见）才把该审查点标记跳过并在报告显著标注。外审自己会先重试一次，输入不缩减：超时就降一档推理强度再跑，普通失败原样再跑；额度、鉴权、没安装这三种不做无谓重试，直接降级。

代价如实：替身与被审代码出自同一家族的模型，少了异构引擎交叉验证这一层，所以发生任一失败性降级时可信度评级封顶 B（替身保住的是审查覆盖，不是评级）。装好命令行工具 / 额度恢复后无需重新配置，下次运行自动用回异构外审。

偏差容忍 5% 到底是什么意思？研报年化 10%，容到 10.5% 还是 15%？

是 10.5%。判定用相对偏差：|复现值 − 研报值| ÷ |研报值| ≤ 容忍度。研报 10%、容忍 5% ⇒ 区间 9.5%~10.5%；你自定义 10% ⇒ 9%~11%。

想要「±5 个百分点」这种绝对偏差语义的话，编辑你目录里的 templates/standards.json 给特定指标配 abs_eps。

报告评级 C，是复现失败了吗？

不一定。C 的字面判据是「存在核心要素未复现」——常见成因是研报依赖的某类数据你本地没有（系统会穷尽核实后正式降级，理由与证据落档）。看报告结论区：会写明 C 的成因、报告落脚点结论是否受影响、残余偏差的逐条归因。真正要警惕的是无归因的偏差——而那过不了结果审计门禁。

样本外分析是什么时候做的？结论怎么读？

复现达标（pass 或 partial）后自动触发：把复现好的策略原样（零参数改动）延伸到研报回测区间之后的数据上运行，产出样本内外指标对比、净值延伸图与四选一结论——延续 / 衰减 / 失效 / 样本不足（样本外不足 60 个交易日时强制标注统计意义有限）。判读阈值写在 oos_report.md 里。门禁会核验样本外区间与研报区间零重叠，防止样本内数据冒充样本外。若你本地数据还没超出研报区间，该阶段自动跳过并留痕。

研报某处写得含糊，系统怎么处理？

提取阶段登记为歧义（分级：blocking / major / minor）。auto 模式下按最合理解释设为假设、高亮登记（major-auto），跑完统一在报告里呈现，每条附 revise 命令供你改口径重跑；interactive 模式下 blocking 级歧义直接挂起（paused_blocked），把候选解释与影响呈给你裁决后继续。

我有自己的回测框架，怎么让它用我的？

setup 第四项填你框架的目录路径（或编辑 .reproduce.json 的 backtest_framework）。复现规划与实现合同会收到指令：回测执行层优先调用你的框架、内置 common/ 只补缺口。输出产物格式与门禁要求不变，所以对数、审计、报告都照常。

怎么调整某个特定指标的容差，而不是全局容忍度？

直接编辑你目录里的 templates/standards.json——它在 setup 时作为种子拷贝到你目录，本来就是给你调的。按报告类型分节，每个指标可配 max_rel_dev（相对偏差上限）、abs_eps（近零绝对偏差）、require_same_sign（同号要求）、order_of_magnitude_only（仅量级）。全局偏差容忍与之的关系：非空时统一替换所有 max_rel_dev，其余语义保持。

流水线跑一半会话断了 / 想换台机器继续？

/reproduce continue <id>。全部进度在 workspace/{id}/state.json、事件流与产物文件里，续跑从步骤级恢复：已点收的步骤不重做，中断时在途的工单重新列出后重派。换机器把工作目录同步过去即可。

复现海外报告/论文，本地没有原文市场的数据怎么办？

用实验模式：起跑时加 --experimental。规划阶段会把原文不可得的数据映射为本地等价替代（如美国 CPI → 中国 CPI、SPX → 沪深300），每个替代都登记进假设登记簿；复现目标从「数值对齐原文」变为「该方法在迁移市场是否成立」——数值达标判定整体豁免（效应存在与否都是有效结论），但数字与产物的一致性照样被反虚报审计盯着（数字不能编）。最终报告与 HTML 结果页会强制显著声明这是市场迁移复现，门禁核验该声明缺失过不了关。若你没加 flag 而规划阶段发现原文市场整体不可得，系统会挂起询问你是否切换，不会擅自决定。

报告被分诊为 hard，跑得又慢又贵怎么办？

先看分诊依据（plan.md 的难度判定节）。v2.6.0 起判据以方法复杂度为主轴：只有训练模型 / 优化求解 / 多资产联动才 hard，结果表多、指标多属于"工作量大"，只影响里程碑数量不抬难度档。若仍觉得过重：起跑时 --difficulty medium 直接覆盖分诊；配置 economy: true 让机械性角色降为 sonnet；把 audit_level 调为 standard 让规格/代码外审只在关键条件下触发。三者叠加约可省三分之二 token 消耗。v2.7.0 又叠加了墙钟流水线（自动生效无需配置）：milestone 验证与下一段编码重叠、代码外审与运行验证默认并行、结果审计与样本外分析并发——medium 每跑再省约半小时。结果反虚报、达标门禁、人工闸门一处不动。

v3 从另一头下手：此前每次派发子 agent 都要把规格书、假设登记簿、覆盖矩阵整份读一遍，编排会话自己还要读执行卡、手写派发提示词。现在每一步只拿到一份按需切好的任务文件，编排会话只做取工单与点收。用三个历史案例的终态文书离线试切，写码角色的任务文件约为原先整份文书的三成；真实跑下来省多少以 flow cost <id> 的记录为准，每个案例都能自己查。

它停下来问我了，我怎么回答才算数？

直接在对话里回答就行：编排会话会把审阅包的要点和各选项的后果讲给你，你选定后它把你的原话交回内核。在 Claude Code 里，钩子会在你提交输入时记下这句话作为凭据（钩子级）。你也可以在自己的终端里执行 flow decide，按提示输入检查点短码（终端级）——短码写在审阅包和看板上。两者都没有时放行照样生效，但记为「自述级」并在看板和报告附录里标出，方便你事后核对「这一步真是我批的吗」。

我想知道它现在在干什么、卡在哪、花了多少？

打开 workspace/<id>/board.html（浏览器直接打开的静态页，运行中会自动刷新）：当前步骤、等谁、停了多久、各阶段门禁结论、待决检查点、返工派发清单、用量都在上面。全部案例的总览在 workspace/board.html。终端里对应 flow status 和 flow cost <id>。在途的一步超过 3 小时（可配）没有新进展，状态和看板会告警并开检查点。

研报要用的数据我本地不全，会怎样？

规划阶段内核会逐条核对数据需求，把缺口连同证据列给你（缺哪段、哪些年份标的数塌陷、影响哪些指标），然后停下等你选：补数据、等价替代、缩小范围、先用模拟数据试跑、砍掉相关要素、终止。它不会自己替你降级。想无人值守时让它先试跑，建案时加 --on-missing mock：缺口会按「先试跑」处理，跑通后停在「试跑完成」——试跑不出达标结论、不写报告。详见上文「数据体检与缺口处置」。

v2 跑到一半的旧案例，升级到 v3 之后怎么办？

不用动，也不会被自动迁移。旧案例续跑时内核只给出「按旧执行卡做」的工单，行为与 v2 一致（旧执行卡保留在插件里）。想把某个旧案例交给内核推进，需要先把它的状态文件升级到新格式（flow migrate <id>，会留一份原文件备份）——这一步编排会话会先征得你同意，不会擅自做。升级后的状态文件 v2.12 及更早的工具读不了；要退回，用备份覆盖回去并删掉新生成的事件流文件即可。

在 Codex 里用和在 Claude Code 里用有什么不同？

流程、门禁、角色、产物完全相同，同一个案例可以在两边接着跑。差别有三处：外审引擎相反（Claude Code 里用 Codex 审，Codex 里用 Claude Code 审）；Claude Code 有钩子（禁读护栏当场拦截、放行凭据可达钩子级），Codex 没有对应的拦截点，改为事后从会话记录核对，放行凭据最高到终端级；Codex 沙箱不能联网时外审会失败并自动降级。其他能读任务文件、能派子代理的宿主走通用适配卡，同样可用。

怎么更新插件？

/plugin update quant-report-reproduce（重启会话生效）。你目录里的 templates/common 不会被自动覆盖——setup 重跑时会列出「插件侧较新」的文件清单，由你决定是否手动同步。Codex 侧工作目录里的角色文件（.codex/agents/）同样不会被覆盖；它们落后于新版合同时内核会自动改用通用子代理并内嵌新合同，想用回命名角色就删掉旧文件后重跑 setup。

维护者说明

面向插件维护者（仓库所有者）的分发与同步约定；普通使用者可跳过本节。

  • 分发一律用 git URL：marketplace add https://github.com/Hedicx2020/ghquant_plugin 只取 git 跟踪内容（约 4.6M）。marketplace add <本地路径> 会全量拷贝目录——含 .venv、output/ 等被 gitignore 的内容（实测 400M+），仅限本机自测。
  • 公开仓库是脱敏快照：远程 main 由 pub_snapshot 孤儿分支强推而来，不带开发历史，且剔除了验收案例文书（workspace/test_v2、src/test_v2）与研报原文 PDF。本地 main 保留完整历史，两者刻意不同源——不要在 main 上直接 git push。
  • 同步公开仓库的流程：用 git worktree 在独立的临时目录里检出 pub_snapshot（不要在主工作目录里切换分支——并行跑着的案例会有未提交的改动）→ 在那个目录里铺上 main 的最新内容 → 剔除脱敏项并核对文件差集 → amend 重写快照提交（提交说明同步版本号）→ 强推到远程 main → 移除临时目录。
  • 路径定位机制：skill 正文不替换 ${CLAUDE_PLUGIN_ROOT}、Bash 也不注入该环境变量（已实测）——工具定位依赖 SKILL.md 协议第 0 级（skill base directory 上两级即插件根），不要在 skill/stages 中引入对该变量的新依赖。
  • 版本与更新：功能变更时同步 .claude-plugin/plugin.json 与 .codex-plugin/plugin.json 两处的 version；使用者 /plugin update quant-report-reproduce 后重启会话生效。用户目录的 templates/common 种子永不被自动覆盖。
  • 角色合同改了要重新生成 Codex 角色文件：uv run python tools/sync_codex_agents.py（加 --check 只检查不写）。.codex/agents/ 若被全局 gitignore 忽略，新增的文件提交时要 git add -f。
  • 内核资产按文件位置定位：步骤表、处理说明（skills/reproduce/explain/）、钩子、外审提示词模板都在插件根，不进种子目录；外审种子模板（templates/codex_prompts/）的占位符集合保持向后兼容，因为用户目录里的副本不会被覆盖。

术语速查

系统的文书（审计意见、门禁输出、覆盖矩阵）使用编号体系保证每条记录可追溯、可机器判定。日常使用不需要记它们——汇报都用人话，代号只在留痕文书里出现。正文中带虚线下划线的代号，鼠标悬停或轻点即可就地查看释义；本表为完整对照，供查阅文书时使用：
